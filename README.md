## 介面與關卡分類（2026-11-20）

- 卡片清單直接顯示 HANS 註冊的鑲嵌部位（武器／盔甲／盾牌／披肩／鞋子／頭飾／飾品），並可按部位篩選；關卡掉落中的卡片也顯示部位。
- 裝備與卡片共用三組效果篩選：角色屬性、攻擊與戰鬥、防禦與生存；移除重複「卡片效果」選項，舊版 `effect=` 分享連結仍能還原至對應的效果條件。
- 關卡預設顯示 17 張，包含 14 張一般遠征、2 張活動（聖誕節、元宵燈會）及 1 張劇情（普隆德拉城）；提供獨立的關卡類別按鈕篩選，舊版 `open=1` 連結仍可還原一般遠征。
- HANS manifest 中每個關卡對應的原站 `maps/<mapId>/minimap.png` 已逐一核實 HTTP 200，圖片直接由原站引用、載入失敗回退地圖圖示；不將 HANS 地圖素材放入公開 repo 或部署檔案。

## 週目卡片／GS／裝備階級（2026-11-20）

- 188 張卡片共用原始效果註冊，按 HANS 的六週目設定動態呈現一至六週目卡片版本（原始、・改、・改²、・改³、・改⁴、・改⁵；效果倍率 1／1.5／2／2.5／3／3.5）。原卡片 ID 加上每週目 1,000,000 的編碼位移；歐西里斯卡片 4144 為**不隨週目放大**的官方例外。保留原卡片的來源與鑲嵌部位，不重複儲存 1,128 張資料。
- 卡片詳情可切換週目、選擇一至三轉的 41 職業，依 HANS 靜態審核的效果函式參數、角色評分權重（`Bk`／`CC`／`TC`）、取整及 mini／MVP 保底顯示卡片 GS 貢獻；**並非整套裝備 GS**。部分特殊卡效果／GS 的面板一致性仍需真機實際比對，不能把推算值當成已逐卡實戰驗證。
- 關卡頁可切換一至六週目；17 張關卡按第一章公式或第二章實際表格顯示選定週目的裝備 Tier 與 GS 入場門檻，活動關卡共用週目規則；劇情限定的一週目不錯誤顯示其他週目掉落。關卡掉落列表的卡片亦同步切換版本與效果。舊連結預設一週目，`?lap=N` 允許直接分享所選週目。
- 裝備頁刻意只保留部位、職業、基礎屬性、掉落反查與 Tier／週目說明；隨機品質、詞綴、精煉 +1～+10、升星可能使最終屬性和 GS 不同，**不產生虛假的固定裝備 GS 或精煉數值表**。
- 重建資料使用經 SHA 審核的 HANS 快照，不執行原始遊戲程式、不將原始圖片或遊戲 bundle 放入 Git／Pages。卡片 GS 仍待遊戲內跨職業與週目樣本校準。

## 技術與驗證

Stack：React 19、TypeScript、Vite；手機 Safari 優先，保留裝備／卡片／關卡／天賦四分頁（**桌面頂部、手機底部**）、中文與英文關鍵字、屬性／職業／部位篩選與反查。

```bash
npm ci --ignore-scripts
npm run typecheck
npm test
VITE_PUBLIC_MODE=1 npm run build
node scripts/verify-public-dist.mjs
```

私有 Dev 預覽：`npm run dev`（此模式可顯示 HANS 原站圖片，不可直接公開部署）。HANS 資料匯入採**當下自行下載、人工驗證、放入 gitignored evidence** 的完整版本快照：

```bash
node scripts/import-hans-source.cjs evidence/hans-20261119
npm run check:source
```

匯入器執行前會校驗 `docs/HANS_SOURCE_AUDIT.json` 固定三個 SHA-256，只執行 TypeScript AST 靜態解析，不執行 HANS 遊戲 JS，不自動下載原始圖片，也不允許其他版本被用作缺失資料備援。更新版本要先重做人工核對並更新審核雜湊；工作流程在 Linux 跑，不使用 macOS runner。

每日的 Source Monitor 僅比較 HANS 公開程式與清單 SHA：真正更新開／更新 GitHub Issue，網站無法連線則維持失敗狀態，不當作資料已更新，不自動修改或部署。

詳細工作狀態與後續事項見 `PROJECT_CONTEXT.md`、`docs/HANS_MIGRATION_PLAN.md`。
