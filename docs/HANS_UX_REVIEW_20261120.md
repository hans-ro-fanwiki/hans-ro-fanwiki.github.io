## 其他值得排程改善（本輪不擴大重構）

### 高優先：資料查詢操作
1. **依關卡看模式的零結果關卡**：目前一旦篩選卡片／屬性，所有關卡仍逐筆出現，點開才發現沒有符合的掉落。建議在篩選條件有效時顯示每關匹配件數，提供「僅顯示有結果的關卡」切換；不可錯誤把當前未開放活動隱藏成資料不存在。
2. **搜尋跨裝備／卡片的維度**：裝備部位 ID 與卡片鑲嵌部位不同（如 `acc` vs `accessory`），跨頁查看更多應保留搜尋詞／效果，但清除不相容的部位／職業條件，避免空白結果。
3. **手機多組篩選高度**：裝備與卡片篩選、關卡類別與週目共用較多首屏空間；可逐步統一「常用條件＋已套用條件」顯示，而不是直接把所有選項隱藏。

### 中優先：細節與資料可信度
4. **卡片 GS 計分**：41 職選單已按轉職分組，但未記憶各職常用偏好；未經遊戲面板校準的分數應持續明示推算。
5. **天賦職業技能圖示列**：目前為只讀 icon，桌面上容易被誤認可配點；後續可標示「僅展示」或增加查閱用途，避免誤以為按鈕失效。
6. **外部圖像載入**：HANS HTTPS 圖片由官方主機載入，已備 fallback；後續維持載入失敗狀態明確，避免重複誤以為圖鑑沒有圖片。

## 驗收與界線

- TypeScript、單元測試、`VITE_PUBLIC_MODE=1` 正式安全建置、`scripts/verify-public-dist.mjs`、Chrome 互動測試與尺寸檢查。
- 檢查鍵盤 Escape／焦點、無搜尋結果恢復入口、已套用進階條件文字，以及四頁互相導覽。
- 目視與基本計算樣本不能替代完整 WCAG 2.2 審計；目前不宣稱已完全符合 WCAG AA。iPhone Safari 真機尚未測試。
- 本輪不更動 188 張卡片、523 件裝備、17 個關卡、天賦配點演算法與分享碼，不混用非 HANS 資料。
